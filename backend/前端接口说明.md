# 专题后端接口 v1

供李京选的前端接入。服务一次加载一个已完成专题，读取原始运行快照，现场构建DAG与基线置信度。无需密钥，不调用模型，不读取参考答案，也不改写原始文件。

## 启动

在 `D:\ai for science\决赛` 目录运行，Python 3.10及以上，仅使用标准库：

```powershell
python backend/serve_api.py --run-dir 'artifacts/full_topic_ai171/run_01' --topic-id ai171
```

默认地址为 `http://127.0.0.1:8502`。启动后用浏览器打开 `http://127.0.0.1:8502/api/topic` 可查看JSON总览。服务没有另建网页。Ctrl+C停止；端口占用会直接报错，可指定 `--port 8503`。

队友电脑接入时：

```powershell
python backend/serve_api.py --run-dir 'artifacts/full_topic_ai171/run_01' --topic-id ai171 --host 0.0.0.0 --port 8502
```

队友将地址改为运行此服务电脑的实际局域网IP，例如 `http://实际IP:8502`；客户端不使用0.0.0.0。当前是无鉴权的局域网原型接口。服务提供浏览器跨域响应及OPTIONS预检，Streamlit也可在Python端直接请求。

所有ID均限定在这个专题和运行内；跨专题关联时同时保存topic_id和run_id。若未指定topic_id，默认取运行目录的父目录名。启动后数据为内存快照；换入新运行结果后需要重新启动。

## 接口

| 方法 | 路径 | 返回 |
| --- | --- | --- |
| GET | /api/topic | 专题标识、模型、规模、问题及最终结论、基线置信度、公式和限制 |
| GET | /api/questions/q_001 | 该问题的双Agent原始意见、完整仲裁、冲突清单、保留意见、重启条件、中间节点及基线分 |
| GET | /api/graph | 完整DAG和节点基线分 |
| GET | /api/graph?question_id=q_001 | 该最终结论的全部上游子图，包括证据、段落、来源和中间判断 |
| GET | /api/evidence/F0002 | 证据、所在段落、完整原文文档、原文高亮切片及被哪些判断引用 |
| POST | /api/recalculate | 基于完整人工覆盖表的重算预览、变化记录及最终结论有效分 |

响应为UTF-8 JSON。未知路径、问题或证据返回404；请求JSON、权重类型或范围错误返回400及 `{"error":"具体原因"}`。POST要求 `Content-Type: application/json`，请求体不超过1MiB。不提供外部原文入库、任意问题输入、模型任务调度或平台鉴权。

## 前端的读取顺序

1. 请求 `/api/topic` 填充问题选择框和最终结论，顶部展示 `questions[].confidence.effective_score`。
2. 选择问题时请求 `/api/questions/<question_id>` 和 `/api/graph?question_id=<question_id>`。
3. 双Agent栏使用 `independent_assessments`；冲突栏使用 `conflicts`。冲突记录的minority_opinion和reopen_condition继续展示，不能只留采信结果。
4. 点击最终或中间节点，按supporting_evidence_ids、conflicting_evidence_ids打开对应证据。
5. 请求 `/api/evidence/<evidence_id>`，先显示段落引用；用户继续查看来源时显示document中的完整原文和content_url。

图谱边的relation为contains、extracts、supports、opposes、premise。方向从来源走向最终结论；下钻沿入边返回上游。source和target均为节点ID。图中没有因果证明；premise采用第六阶段已公开的必需处理步骤规则。

### 原文高亮

证据接口的paragraph包含：

```json
{
  "para_id": "doc_001#p3",
  "text": "完整原文段落",
  "before_quote": "引用之前的原文",
  "quote": "逐字原文引用",
  "after_quote": "引用之后的原文",
  "quote_start": 0,
  "quote_end": 10,
  "offset_unit": "unicode_code_point"
}
```

以上数字仅示意结构，实际偏移由接口返回。三个切片拼接等于text；quote与evidence.quote完全一致。直接把三个字段作为文本渲染，只对quote加高亮，不把原文作为HTML执行。

char_start、char_end是段落在完整document.content中的区间；quote_start、quote_end是引用在段落内的区间，均为从0开始、左闭右开，按Unicode码点计数。JavaScript若使用数字偏移，先用Array.from转换字符数组再切片；使用三个切片字段则不需处理偏移单位。

## 人工修改权重

请求示例，0表示撤销：

```json
{"weights":{"F0002":0}}
```

也可调整中间或最终判断的人工有效分，例如 `{"weights":{"I:q_001:01":40}}`。范围0至100，不能用人工正分恢复失去必需支撑的判断。

每次提交的是本次预览的**完整覆盖表**。例如先改F0002、再改F0033时，第二次请求要同时携带两个键。删除某个键表示恢复默认权重；`{"weights":{}}` 表示全部恢复基线。服务不保存上次请求、不会累积不同用户的修改，所有GET始终返回基线。

PowerShell示例：

```powershell
$body = @{ weights = @{ F0002 = 0 } } | ConvertTo-Json
$result = Invoke-RestMethod -Uri 'http://127.0.0.1:8502/api/recalculate' -Method Post -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$result.conclusions | Select-Object question_id, confidence
```

返回关键字段：

| 字段 | 前端使用方式 |
| --- | --- |
| confidence.weight_overrides | 当前预览的完整覆盖表 |
| confidence.nodes | 全部证据/判断的预览数值和状态，以节点ID索引；用它更新图谱和卡片 |
| confidence.changed_node_ids | 权重覆盖值相对基线发生变化的节点 |
| confidence.recomputed_node_ids | 实际重算的节点，只有变化节点及其后代 |
| confidence.affected_judgment_ids | 需要重新审阅的中间和最终判断 |
| changes | 相关节点的before、after，便于演示变化 |
| conclusions | 各问题原结论文字及预览后的置信度 |

展示effective_score，不将computed_score当成停用/阻断后仍有效的分数。判断的status为active、unsupported、upstream_blocked或disabled；证据为active或withdrawn。人工有效分与公式计算分分开保留，manual_score为null表示没有人工覆盖判断分。

预览返回后不要紧接着用GET的基线分覆盖页面。将该次响应的confidence.nodes按ID应用到已加载的图和问题详情。needs_reassessment为true时明确提示需重新研判；接口仅改数值和有效状态，没有让模型重写原结论。该启发式分数不是正确概率。
