# 决赛后端输入输出字段约定

本阶段对齐《评分标准》附录 A，整理赛方样例中的结构差异与定位问题。产物是参考答案的适配草稿，不是多智能体算法生成的研判结果。

真实模型抽取入口为 `extract_evidence.py`，配置与运行方法见同目录的《抽取运行说明.md》。该入口输出算法抽取的 A.2 证据，与下述参考样例适配草稿分开存放。

## 运行与产物

在“决赛”目录运行，使用 Python 3.10 或更新版本，仅依赖标准库：

```powershell
python backend/prepare_samples.py
```

脚本读取现有六个专题，结果写入 `artifacts/sample_alignment/`。原始样例保持原样。

每个专题输出：

- `questions.json`：只包含 `question_id` 和 `question`，供后续研判程序读取。
- `reference_evidence_draft.json`：按 A.2 对齐字段的参考证据草稿。
- `reference_conclusions_draft.json`：按 A.3 对齐引用的参考结论草稿。

总目录的 `sample_issues.json` 和 `样例问题清单.md` 记录适配操作、定位阻塞项和待核对字段。脚本执行成功只表示适配与报告生成完成；是否存在定位阻塞由报告的 `blocking_count` 表示。

## 输入

后续研判程序的输入为专题原始文档 `raw_documents.json` 与问题清单 `questions.json`。证据样例与结论答案只用于开发对照，不能作为正式研判时的答案输入。

文档字段按 A.1 保留：

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| doc_id | string | 专题内文档标识 |
| title | string | 标题 |
| content | string | 原始正文，保留空格、换行和标点 |
| paragraphs | array | 段落列表，条目包含 para_id、char_start、char_end |

现有样例另外提供 `publish_time`、`source_credibility`、`content_url`，供内部研判使用；发布时间不能直接代替事实发生时间。

段落以 Python 字符串切片 `content[char_start:char_end]` 定位，从 0 开始，结束位置不包含在内。偏移单位为 Unicode 码点；前端若直接使用 JavaScript 字符串索引，需要处理 UTF-16 的差异。

`doc_id`、`fact_id`、`question_id` 会在不同专题中重复，跨专题关联必须同时带专题标识。

## A.2 证据输出

文件顶层为数组，每项包含以下字段：

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| doc_id | string | 原始文档中的文档标识 |
| para_id | string | 原始文档中的完整段落标识，例如 doc_002#p3 |
| quote | string | 对应段落内连续、逐字一致的原文 |
| fact_des | string | 事实描述，与直接引用分开 |
| argument | object | 固定包含时间、主体、地点、内容、影响、数值口径六个中文键，值为字符串 |
| entities | array of string | 实体集合 |

适配器将样例中已出现的 `argument.content` 对齐为 `argument.内容`。缺失键暂填 `""`，并在问题报告中逐条列为待核对；这不代表原文没有对应信息。

正式抽取时，原文无明确时间应填空；统计型事实必须说明统计主体与范围。不能为了填满字段猜测时间、数值或主体。实体、事实描述和结论沿用参考样例，适配阶段不做语义修订。

`quote` 以原始正文及指定段落为准，不进行标点替换、空白清理或同义改写。引用即使能在全文命中，只要跨出指定段落，也会记录定位阻塞；缺文档、缺段落和段落偏移越界同样记录阻塞。

真实抽取使用模型内部字段 `claim_span` 选择段内的连续片段，由程序定位后回填原文 quote。时间采用所在段落的原文表达或空字符串，并用内部 time_role 区分事件、统计截止、通报与未知时间；统计项中的通报时间清空时记录原值与原因。主体、地点允许经原文复核的规范称谓或译名。内部字段不写入 A.2。参考样例适配继续保留原有 quote 与字段，二者不能混为同一结果。

同源信息写入独立的 `source_analysis.json`，通过 evidence_index 关联证据数组，避免给 A.2 增加未约定字段。来源计数是规则估计，不能代替按具体结论识别支持/冲突立场后再做的独立来源计数。

## A.3 结论输出

文件顶层为数组，每项包含以下字段：

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| question_id | string | 问题匹配键，沿用输入值 |
| question | string | 原始问题 |
| conclusion | string | 结论正文，保留必要时点、主体、统计范围与未定论状态 |
| supporting_facts | array | 支撑证据引用，每项仅含 doc_id、para_id |
| conflicting_facts | array | 冲突证据引用，每项仅含 doc_id、para_id |

现有参考结论内嵌 `fact_id`、`doc_id`、`quote` 等字段，却没有 `para_id`。适配器在同一专题内按 `fact_id` 回查证据表，导出对应的 `doc_id/para_id`。内嵌 quote 与证据表不一致时记录待核对项；不会将内嵌文本写进 A.3 的引用列表。

`fact_id`、`conclusion_id`、`verdict_label`、`resolution_type` 及样例证据的字符偏移保留在原始参考文件中。本阶段 A.2、A.3 草稿只导出附录列出的字段；后续内部推理结构单独承载中间结论、依赖和消解记录。

## 内部 DAG 与置信度文件

新增文件不改变 A.2、A.3 字段。`reasoning_graph.json` 顶层为 nodes、edges、topological_order 等；节点ID为 `S:doc_001`（来源）、`P:doc_001#p3`（原文段落）、`F0002`（证据）、`I:q_001:01`（中间判断）、`C:q_001`（最终判断）。节点ID仅在本专题运行内唯一，跨专题必须附专题或运行标识。

中间判断保留原冲突记录中的 result、basis、minority_opinion、reopen_condition、双方引用及处理类型。段落节点保留 text 与原文字符区间，证据保留 quote；前端可从结论沿入边下钻，不需要重查参考答案。

边使用 source、target、relation；支持与冲突角色放在边上，不给证据标记一个全局立场。premise 边表示当前流程将冲突处理步骤作为该问题最终仲裁的必需上游，不表示因果关系。

`confidence.json` 的 nodes 按ID索引；证据有 base_weight、effective_weight、status，判断有 computed_score、effective_score、components、calculation、manual_score、needs_reassessment。calculation 保存逐组候选、代表证据、最大权重及分子分母等；公式与限制写在顶层 formula。人工重算使用相同结构的 confidence_after.json，intervention.json 保存权重覆盖表、受影响ID和前后结果。详见《专题流程运行说明》。

## 本阶段完成标准

运行脚本可生成六个专题的问题清单与字段对齐草稿，并列出不能逐字定位的证据、缺失字段和引用文本差异。草稿仍需按问题报告处理，不作为正式提交物或算法效果证明。
