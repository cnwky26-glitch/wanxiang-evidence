# 原文到证据 JSON 的运行说明

输入为原始文档和问题清单，输出为附录 A.2 的证据数组及同源分组结果。模型选择段落中的连续事实片段并填写结构化事实，程序逐字定位该片段后，从原文回填 quote。

完整专题的双角色独立研判、结论与冲突仲裁使用 run_topic.py，见同目录《专题流程运行说明.md》。本文件说明仅抽取与去重的入口。

## 模型服务配置

用户已选定 DeepSeek，入口使用其官方 Chat Completions 接口，默认配置为：

- 服务地址：`https://api.deepseek.com`。
- 模型：`deepseek-flash`。
- 思考模式：关闭。
- 输出：JSON 模式，最多 32768 个输出 token，temperature 为 0。

服务地址和模型已写入入口代码，只需配置 `DEEPSEEK_API_KEY`。

在 Windows“编辑账户的环境变量”中新增用户变量 `DEEPSEEK_API_KEY`，值填写 DeepSeek 官方平台签发的密钥，然后新开终端。密钥无需写进源码或聊天。

如果需要让已经打开的 PowerShell 终端读取刚保存的用户变量，执行：

```powershell
$env:DEEPSEEK_API_KEY = [Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY', 'User')
```

配置依据：[DeepSeek 官方调用说明](https://api-docs.deepseek.com/)、[Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON 输出要求](https://api-docs.deepseek.com/guides/json_mode/)。JSON 模式不代替字段与引用校验；空内容、截断和无效引用仍会直接报错。

## 运行

在“决赛”目录执行，Python 3.10 或更新版本，仅依赖标准库：

```powershell
python backend/extract_evidence.py --documents '原始文档JSON的路径' --questions '问题清单JSON的路径' --output '本次运行的新输出目录'
```

`--documents` 接收符合 A.1 的文档数组；`--questions` 接收包含 `question_id`、`question` 的数组，可使用此前适配生成的 `questions.json`。模型请求只带问题与原文，不读取证据参考答案或结论参考答案。

程序按原文段落分批，目标为每批约 24000 字符，保留完整段落。首次模型联调使用少量文档即可；批次数量会影响模型调用次数。

已准备单文档联调输入，来自 AI171 专题原始文档 `doc_002`，仅配该专题问题 `q_001`，未使用参考答案。在“决赛”目录运行：

```powershell
python backend/extract_evidence.py --documents 'artifacts/extraction_trial/input/raw_documents.json' --questions 'artifacts/extraction_trial/input/questions.json' --output 'artifacts/extraction_trial/manual_run_01'
```

该次调用只验证单文档的 API、字段与原文回填链路，不代表完整专题研判或客观分实测。再次运行时请使用新的输出目录。

运行后包含：

- `extract_001.json`、`review_001.json` 等：各批抽取和原文复核的模型原始响应。
- `evidence.json`：所有批次成功后生成的 A.2 证据数组。
- `source_analysis.json`：来源分组、规则命中依据、每条证据对应的来源组及计数。
- `run.json`：成功运行的输入路径、模型、批次数和证据数。
- `normalization_log.json`：清除不适用的统计时间等操作记录。

接口报错、响应截断、字段不合约定、事实片段无法定位，或有效时间在所在段落没有直接文本依据时，程序直接报错。英文片段仅大小写不同且可唯一定位时，会复制原文并记录定位操作。主体和地点允许经过原文复核的规范称谓或译名。已收到的响应保留在本次目录中；只有完整运行成功才生成 evidence.json 和完成记录。程序不猜填日期。对统计事实的通报/获悉时间，按时间角色清空并显式记录原值与原因。

同一输出目录可复用已经完成且请求正文完全相同的响应，继续中断阶段。输入或提示发生变化时会报错，需使用新目录。

## 当前引用粒度与验证边界

当前模型内部增加 `claim_span`，表示所选段落内连续的事实片段；该字段不进入 A.2 提交格式。程序定位后复制原文作为 quote。时间暂保留所在段落的原文表达，不直接转换成带推测年份的日期；统计时间与通报/获悉时间分开处理。主体、地点的规范化依赖原文复核，不以逐字字符串相同代替语义判断。

这些约束保证字段具有直接文本出处，不自动证明主体角色、时间语义、事实拆分及数值口径全部正确；相关性和语义准确性仍需在后续评测中衡量。

## 同源分组与统计

`source_dedup.py` 使用三条规则：同一文章地址、去空白后相同正文，以及“相同的明确通稿来源＋正文高度相似”。规则细节和每次命中依据都写入 source_analysis.json。所有原文、证据和不同版本均保留，分组不删除材料。

`evidence_sources` 按 evidence.json 的从0开始索引，为每条证据标明 origin_id。文档与来源组标识均在当前专题内使用，跨专题需附带专题标识。

`source_group_count_estimate` 为全部输入文档的来源组数；`independent_source_count_estimate` 只计算实际有证据的来源组。它们是文章层面的规则估计，不能作为已证明相互独立的信源数，也不能直接当作某一结论的赞成票数。改写转载、复合来源文章和未明示的共同消息源可能未被识别。

已有证据可以只运行本地同源分析，避免重新调用模型：

```powershell
python backend/deduplicate_sources.py --documents '原始文档JSON的路径' --evidence '已有evidence.json的路径' --output '已存在目录中的新source_analysis.json路径'
```

本入口覆盖证据抽取与来源分组；完整专题入口已增加双角色独立研判、A.3 结论与基础冲突仲裁。DAG、置信度重算及前端联调仍按后续步骤推进。
