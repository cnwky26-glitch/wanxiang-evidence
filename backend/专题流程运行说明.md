# 完整专题研判流程

入口为 run_topic.py，输入原始文档和问题清单，依次生成证据、来源分组、两角色独立意见、最终结论、依赖 DAG 和置信度分项。运行时不读取证据参考答案或结论参考答案。

## 流程

1. 按原文段落分批抽取证据草稿。
2. 每批结合原文复核草稿，修正多项事实合并、时间角色混用和无关背景。
3. 定位事实片段并复制原文，处理时间角色，结合原文复核主体、地点等语义字段，生成 A.2 证据。
4. 按已有规则计算来源组，保留每份文档和每条证据。
5. Agent A 事实研判员与 Agent B 反证核查员在独立会话中分别回答全部问题，两者不读取对方输出。
6. 协调员结合双方意见与证据仲裁，输出 A.3 结论、逐项冲突记录、保留意见和重新评估条件。
7. 将已有冲突处理结果作为中间判断，生成来源→段落→证据→中间判断→最终结论的 DAG，并计算置信度。

两角色及协调员使用同一 deepseek-flash 模型，角色提示与会话分开；不声称它们是不同基础模型或统计上相互独立。

## 运行

配置 DEEPSEEK_API_KEY 后，在“决赛”目录使用 Python 3.10 或更新版本运行。全部代码使用标准库。

```powershell
$env:DEEPSEEK_API_KEY = [Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY', 'User')
python backend/run_topic.py --documents '多智能体可信研判与证据链溯源/样例集-拓尔思-20261012/印度航空 AI171 空难（2025.6–2026.5）/raw_documents.json' --questions 'artifacts/sample_alignment/印度航空 AI171 空难（2025.6–2026.5）/questions.json' --output 'artifacts/full_topic_ai171/run_01'
```

运行目录会保存输入快照、各阶段请求与原始响应。中断后执行相同命令，会复用相同请求的已完成响应，继续未完成阶段；输入或请求发生变化时会报错，需另用新目录。请求文件不包含密钥或鉴权头。

## 时间与质量边界

模型内部的 fact_kind 区分统计、表态和其他事实；time_role 区分事实发生、统计截止、通报/获悉和未知时间。对统计事实，通报或记者获悉时间不会被直接写成事实时间；若模型仍填写，程序清空并记录原值与操作依据。原始模型响应和原文不被修改。

英文片段选择若只与原文有 ASCII 大小写差异，且可唯一定位，程序会记录该情况并复制原文原有大小写；输出 quote 始终来自原文，不修改字词或数字。无法定位或仅按大小写仍有多个匹配时直接报错。

主体、地点允许经过原文复核后的规范称谓或译名，例如英文 Air India 对应中文“印度航空”，不要求中文译名逐字出现在英文原文中。有效时间须能在所在段落直接找到，时间角色另行判断。

文本定位和格式检查不代替语义判断。复核模型仍可能有错；来源组仍是规则估计，不能证明消息源真正独立。最终结论只依据本次输入材料，不能当作真实事件的权威调查结论。

本入口已包含前六阶段的功能链路。已有 run_01 的历史 run.json 保留原运行记录，不回写为当时已包含第六阶段。离线补算结果单独放在 stage_06。

## 离线生成图谱及人工重算

无需密钥，不调用模型，也不重新抽取原文：

```powershell
python backend/build_reasoning.py --run-dir 'artifacts/full_topic_ai171/run_01' --output 'artifacts/full_topic_ai171/stage_06' --weights 'artifacts/full_topic_ai171/stage_06/manual_weights.json'
```

不指定 `--weights` 时仅输出基线。人工权重文件为 JSON 对象，例如 `{"F0002": 0}`；证据权重范围0至100，0表示撤销。`I:q_001:01` 等中间判断、`C:q_001` 等最终判断也可指定人工有效分；不能用正分恢复已经失去必需支撑的节点。每次 CLI 都从基线应用该文件中的完整覆盖值，不自动累积上次修改。

额外输出 `confidence_after.json`、`intervention.json` 和 `DAG与置信度重算.md`，包含前后值、受影响节点、概览图及逐项演算。源 run 目录不被修改。使用新的输出目录保存不同干预方案；指定同一输出目录会覆盖本次生成的同名文件，展示时以本次命令实际生成的文件为准。

前端后续可直接调用 `reasoning.build_graph(documents, evidence_index, arbitration)` 及 `reasoning.calculate_confidence(graph, weights, previous)`；`previous` 必须是同一图的上次结果。`weights` 是完整覆盖表，删除某个键表示恢复该节点的默认值。有 `previous` 时只重算权重变化的节点及其后代，`affected_judgment_ids` 给出需要重新审阅的中间和最终判断。

每条边的 `relation` 为 contains（来源包含段落）、extracts（段落抽取证据）、supports、opposes 或 premise（中间处理步骤供最终仲裁使用）。支持/冲突角色属于具体边；同一证据在不同判断中可以扮演不同角色。最终判断将该问题全部冲突处理步骤视为必需上游，这是当前保守的计算规则，不代表模型已经证明每条隐含逻辑依赖。

## 置信度规则

总分 = 0.50×信源分 + 0.30×一致性分 + 0.20×推理链分。

- 信源分：支持侧按 origin_id 分组，每组取最大有效权重 w，计算 sum(w²)/sum(w)。证据默认权重为数据集 source_credibility_prior×100，不按转载篇数或重复引用累加。
- 一致性分：支持强度 S 和冲突强度 R 分别为各侧每组最大权重之和；有效来源组并集不足2组时取50，否则为100×S/(S+R)。无支持则为0。同组同时出现两侧时保留内部矛盾，独立来源计数仍只计一组。
- 推理链分：先计算支持来源组有效覆盖率，再与所有必需中间判断的有效分取最小值；没有中间判断时等于覆盖率。任何必需中间判断失效时，最终判断标记 upstream_blocked，有效分为0。
- 计算不提前舍入，页面或报告展示保留两位小数。JSON 记录完整中间数、逐组代表证据、支撑和冲突强度、覆盖率及上游分数。

这是团队选定的启发式指标，未校准为正确概率。链路分只衡量支撑覆盖和上游分数，不能验证逻辑正确性。一致性依照仲裁引用角色计权，保留不同时点、口径或不确定性讨论的双方材料也可能降低该分项，不能把它直接解释为最终结论不正确。中间节点来自已有冲突处理记录，图谱不是因果证明。

人工修改会更新分数、有效状态及 needs_reassessment 标记，不自动改写模型原结论。必须重新审阅的结论不能凭新分数直接当作已重新研判。
