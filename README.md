AI for Science · OPC创新挑战赛项目的后端与前端联调样例。当前包含证据抽取、规则同源分组、双角色独立研判、冲突仲裁、推理依赖DAG、启发式置信度与人工权重重算。

本仓库提供一个已完成专题的运行快照，供队友直接接入前端。GitHub用于代码与数据版本同步；接口服务由各自电脑启动。

## 启动现有专题接口

需要Python 3.10及以上，仅使用标准库。克隆仓库后，在包含backend和artifacts的项目根目录执行：

```powershell
python backend/serve_api.py --run-dir 'artifacts/full_topic_ai171/run_01' --topic-id ai171
```

打开 <http://127.0.0.1:8502/api/topic> 可查看JSON总览。保持终端运行，Ctrl+C停止。这个入口读取已有结果，不调用模型，无需DeepSeek密钥。

## 前端接入

[完整接口说明](backend/前端接口说明.md)包含局域网启动、字段说明、原文高亮与权重重算示例。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/topic | 专题规模、问题、最终结论及基线置信度 |
| GET | /api/questions/q_001 | 双Agent意见、仲裁、冲突、保留意见和中间判断 |
| GET | /api/graph | 完整依赖图及基线分 |
| GET | /api/graph?question_id=q_001 | 单个问题的全部上游子图 |
| GET | /api/evidence/F0002 | 证据、段落、原文、高亮切片及引用关系 |
| POST | /api/recalculate | 人工权重重算预览 |

修改权重时提交完整覆盖表，例如 `{"weights":{"F0002":0}}`。提交 `{"weights":{}}` 恢复基线。GET始终返回基线；POST只预览数值与有效状态，不保存修改，也不改写原模型结论。

## 目录

- backend/：抽取、研判、仲裁、图谱与接口代码，以及字段和运行说明。
- artifacts/full_topic_ai171/run_01/：当前AI171专题的输入快照、证据、双角色仲裁、来源分组与结论。

样例覆盖52份原文、208条证据、3个问题；服务构建的DAG含7个中间判断。A.2为evidence.json，A.3为conclusions.json。run.json是原模型流程的历史记录；接口启动时使用当前代码构建图谱和置信度。

真实模型流程入口为backend/run_topic.py，运行方式见[专题流程运行说明](backend/专题流程运行说明.md)。它需要单独提供原始文档和问题文件，并在本机配置DEEPSEEK_API_KEY。完整赛方原始材料与模型请求/响应缓存保留在本地，未作为本仓库的接口运行依赖。

## 当前状态

前六阶段已有首版功能；第七阶段后端接口及一次本机HTTP完整流程通过。现已增加直接读取本地 JSON 的 Streamlit 交互演示，完成原文下钻、高亮、双角色仲裁、依赖图谱和权重预览，并通过10项数据与交互测试及本机浏览器操作验证，见 [验证记录](VERIFICATION.md)。此演示不依赖 HTTP 后端；跨电脑/局域网接口联调、集中语义评测及最终验收仍需完成。

当前结果尚有已记录的语义质量遗留：人数结论开头措辞偏笼统，座位问题判断较参考答案保守，部分事实原子性仍需集中处理。格式与逐字定位通过不代表语义全部准确，不应作为正式评分或最终提交验收结论。

置信度采用团队选定的0.50信源分＋0.30一致性分＋0.20推理链分，未经概率校准。来源组是规则估计，不能证明真实消息源相互独立；图谱表示引用和仲裁处理依赖，不证明因果。两角色使用同一基础模型的独立会话。
